Part 1 · Real Intelligence (20 pts)
⭐ Multi-layer AI — Not Just API Calls
What the AI Actually Does
Intelligence Layer 1 — Per-Violation Fix Generation

What Claude does: For each new critical/serious violation, the workflow sends Claude the violation's rule_id, WCAG criterion, impact level, affected HTML snippet, and CSS selector. Claude returns a structured JSON object with a plain-English explanation, the exact HTML code change required, estimated developer time, and risk level.

Why this is real intelligence: Claude doesn't just reformat the violation data — it reasons about what the HTML needs to be to pass the WCAG criterion. A contrast violation on #F5A623 background returns the specific replacement color (#B5720A) and the new ratio (5.2:1), not a generic "darken the color."

Intelligence Layer 2 — Pattern Detection + Root Cause

What Claude does: The executive summary section of the report is generated by a separate Claude call that receives the full diff report (all violations across all pages) and identifies: the most likely root cause, the component or deployment that introduced the regressions, the estimated total fix time, and a legal risk assessment.

Example from test run: Claude identified that 4 of 7 violations traced to a single <PricingCard> component deployed 3 days prior — a root cause a simple rule-based system couldn't detect. This is pattern reasoning, not just data retrieval.

Intelligence Layer 3 — Smart Routing (Saves Cost)

Node 7 (Filter) makes an intelligent decision: only critical and serious new violations go to Claude API. Moderate and minor violations receive rule-based suggestions from the Assignment 3 reference dataset. This reduces Claude API calls by ~30% on average while maintaining quality on the violations that matter most.

This is a real product decision — not just "call Claude on everything." It demonstrates understanding of cost/quality tradeoffs in production AI systems.

Intelligence Layer 4 — Diff Engine

The diff engine identifies NEW vs PERSISTING vs RESOLVED violations by comparing SHA-keyed violation IDs against the previous scan. Only new violations trigger AI analysis — a violation present since last week doesn't get re-analyzed, preventing the same issue from consuming API credits every scan.

This is the decision-making intelligence that makes the system economically viable at scale. Without it, cost per run scales linearly with total violations, not new violations.

Claude Prompt Architecture

System Prompt (per-violation call)

// Structured output enforcement You are an expert web accessibility engineer. Analyze the WCAG violation and return a JSON object with exactly these fields: - plain_english: 1-2 sentence explanation for non-technical stakeholders - impact_statement: who is affected + how - code_fix: specific HTML/CSS/JS change (show old and new code) - estimated_time: developer time to fix - risk_level: Low / Medium / High Return ONLY valid JSON. No markdown, no preamble.

Error Handling — What Happens When Things Go Wrong
## Error Handling — Accessibility Monitor v2 What could go wrong: - Claude API rate limit exceeded (429 response) - Claude returns malformed JSON (parse error) - GitHub API rate limit (403 — 60 req/hr unauthenticated) - Playwright crawl timeout (SPA takes >30s to load) - SendGrid delivery failure (invalid email / quota) - n8n memory exhaustion (>380 items in Code node) How we handle it: - 429 from Claude → continueRegularOutput + 5s retry, max 3 attempts If all retries fail: violation gets rule-based suggestion, not AI suggestion - Malformed Claude JSON → try/catch in Node 9 → fallback plain text suggestion Parse error is logged in violation record (parse_error: true flag) - GitHub 403 → continueRegularOutput → workflow continues with W3C + RSS sources Minimum 153 records still collected without GitHub - Crawl timeout → page skipped, logged in crawl_error_log.txt Scan continues with remaining pages - SendGrid failure → logged, HTML report still saved locally Next run will include missed report in digest - Memory exhaustion → Switch to Split in Batches node (50 items/batch) Prevents heap allocation failure at >380 simultaneous items

What Breaks First — In Order

1. n8n memory (hard failure) — heap exhaustion at ~380 simultaneous items in a Code node; this is what killed the 100-domain run. Fix: Split in Batches node (50/batch).

2. Claude rate limit (recoverable, burst-only) — 130 calls over ~8 min at 50 domains never tripped it (~16/min); it only appears as short 429 bursts near ~280 concurrently-queued items. Fix: Split in Batches caps concurrency, or Tier 2 (2,000 RPM).

3. Playwright timeouts — ~2–3% of pages on JS-heavy SPAs. Fix: Increase timeout to 60s, add retry.

4. Cost at scale — Not a breaking point, but at 1,000 domains/day cost would be ~$13.50/day (~$405/month). Still well below any enterprise budget.

Production Readiness

Run 24/7? Yes — with batch processing (50 violations/batch) and Claude Tier 2.

Single domain reliability: High — 0 errors across 50+ runs.

Monthly cost @ 100 domains/day: ~$78/month.

SLA achievable? <30s per domain — yes.

Required monitoring: Claude API dashboard (token usage), n8n memory metrics, pipeline_error_log.txt, crawl success rate (target: >95%).

Could a company pay for this? Siteimprove charges $500–$3,000/month. This runs at $78/month. The ROI is obvious.

Optimization Path to Production Scale

To handle 1,000 domains/day: (1) Add Split in Batches node — process violations in groups of 50. (2) Upgrade Claude to Tier 2 (2,000 RPM). (3) Add Redis queue to decouple crawl jobs from AI processing. (4) Cache WCAG lookups — 258-record reference dataset is static, load once. (5) Parallel domain processing — n8n worker queue can handle 5 domains simultaneously. Projected result: 1,000 domains in ~2.2 hours overnight batch at ~$13.50/day.

Web teams have no continuous, automated signal for accessibility regressions — they discover WCAG failures an average of 18 days after introduction, only when a user complains or an audit is scheduled. 96.3% of websites have detectable WCAG failures. 4,605 ADA lawsuits were filed in 2023 alone.

A multi-agent n8n pipeline that crawls registered websites weekly, audits all pages with axe-core v4.10, diffs violations against the previous scan, sends new violations to Claude for plain-English fix suggestions, and delivers a complete HTML audit report via email — all in under 30 seconds per domain.
